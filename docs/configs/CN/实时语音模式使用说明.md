# 实时语音模式使用说明

> **适用范围**: VAD button、实时语音打断、ASR 自动提交  
> **入口**: 聊天输入框当前麦克风按钮旁边的实时语音开关  
> **最后更新**: 2026-06-19

本文面向联调和使用者，说明如何开启实时语音模式、如何判断链路可用，以及常见问题如何处理。

---

## 1. 功能边界

实时语音模式不是传统按钮式 ASR。两条链路并存：

| 功能 | 入口 | 行为 |
| --- | --- | --- |
| 按钮式 ASR | 原麦克风按钮 | 录一段完整音频后，通过 ASR 转写并填入输入框。 |
| 实时语音模式 | 新增 VAD button | 持续发送麦克风音频，后端实时判断开口和说完。 |

实时语音模式开启后，用户开口会触发：

1. 后端发送 `control:interrupt`。
2. 前端停止当前 TTS 播放和播放队列。
3. 后端取消旧 LLM generation。
4. 用户说完后，后端提交 ASR。
5. ASR 成功后，后端自动进入新一轮聊天。

---

## 2. 使用前条件

实时语音 button 只有在以下条件满足时才可点击：

1. ASR 模块已启用。
2. 已选择聊天角色。
3. 已创建并打开有效聊天窗口。
4. 当前聊天不是 `draft_` 临时聊天。
5. 业务 WebSocket 已连接。

如果按钮不可用，把鼠标悬停在按钮上可以看到禁用原因。

---

## 3. 推荐配置

完整实时语音闭环推荐使用：

```yaml
# config/vad_config.yaml
enabled: true
vad_model: silero_vad
```

```yaml
# config/asr_config.yaml
asr_model: sherpa_onnx_asr
persistent_provider: true
preload_provider: false
```

如果 `asr_model` 是 `web_speech_api`，实时打断仍然可用，但后端无法在 `speech_end` 后自动 ASR 和自动聊天。

---

## 4. 手动联调步骤

1. 启动后端和前端。
2. 打开聊天页面。
3. 选择角色，例如 `atri`。
4. 创建或打开一个正常聊天窗口。
5. 打开浏览器 DevTools。
6. 进入 `Network -> WS -> /ws -> 消息`。
7. 让角色先输出一轮回复。
8. 点击实时语音 button。
9. 对麦克风说一句话。
10. 等待后端 ASR 和新一轮聊天输出。

正常情况下，WS 消息中应看到类似顺序：

```text
input:audio:chunk
control:listen-state
control:interrupt
output:asr:transcript
output:chat:chunk
```

如果是在 AI 正在流式输出时开口，还应看到：

```text
output:chat:interrupted
```

---

## 5. 如何判断成功

### VAD 实时音频链路成功

你能看到前端持续发送：

```text
input:audio:chunk
```

后端持续返回：

```text
control:listen-state
```

### 打断成功

用户开口时能看到：

```text
control:interrupt
```

如果 AI 正在输出文本，后续不会再看到旧 `generation_id` 的 `output:chat:complete`。

### ASR 自动提交成功

用户说完后能看到：

```text
output:asr:transcript
output:chat:chunk
```

这说明链路是：

```text
VAD -> ASR -> 后端自动聊天
```

不是传统按钮式 ASR，也不是手动文字输入。

### 被打断回复处理成功

AI 正在输出时被打断，应能看到：

```text
output:chat:interrupted
```

该半截回复会在前端展示，并写入可审计的 `chat_history`，但不会作为普通完整回复进入短期记忆。

---

## 6. DevTools 查看位置

业务 WebSocket 是：

```text
/ws
```

如果你看到类似：

```text
ws://localhost:5200/?token=...
```

这是 Vite HMR 通道，不是业务聊天 WebSocket。

在 Chrome DevTools 中，需要点进单条 `/ws` 连接，再查看“消息”面板。消息会按帧列表显示。

## 7. 常见问题

### 打开 button 后没有 ASR 自动聊天

检查 `config/asr_config.yaml`：

```yaml
asr_model: sherpa_onnx_asr
```

如果当前是：

```yaml
asr_model: web_speech_api
```

这是预期限制。`web_speech_api` 只能在浏览器侧识别，后端不能拿它做 VAD 后的自动 ASR。

### 控制台出现 ScriptProcessorNode 弃用警告

这是当前前端采集实现使用 `ScriptProcessorNode` 导致的浏览器警告。它不代表功能失败。

迁移到 `AudioWorklet` 是后续优化，不属于当前实时语音 MVP 的必需条件。

### 说话结束判断太快

当前 Silero 默认静默结束理论时间约 `768 ms`：

```text
required_misses = 24
24 * 32 ms = 768 ms
```

连续说话被切分时，可以增大 `config/vad_config.yaml`：

```yaml
silero_vad:
  required_misses: 30
```

### 误触发太多

优先调高：

```yaml
silero_vad:
  prob_threshold: 0.5
  db_threshold: 65
```

也可以适当调高 `required_hits`，让用户开口判定更保守。

### button 错误提示会不会一直叠加

不会。新的错误会覆盖旧错误；错误提示显示 3 秒后自动清除。

---

## 8. 当前限制

1. TTS 仍然是 REST 完整音频返回，不是 WebSocket 音频流。
2. VAD 打断会停止旧 TTS 播放，并丢弃旧 generation 的后续 TTS 结果。
3. 已发出的 REST TTS API 请求不做 provider 级取消。
4. `web_speech_api` 不能用于后端 VAD 自动 ASR。
5. 当前实时音频 payload 是 JSON float array，后续可评估二进制帧优化。
